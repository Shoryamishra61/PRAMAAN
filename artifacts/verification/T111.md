# T111 acceptance evidence

## Requirements

`PRD-022`, `PRD-NFR-004`, `SRS-027`, `API-011`.

## Defect and root cause

The BLOCK/PASS/REVIEW preset controls populated form fields but did not execute the verifier. At the
current in-app-browser width, the responsive layout also placed output below the long form, so even
a real fast response provided no observable feedback. The result felt like an inert static page.

## Acceptance tests

- preset controls are labeled as actions and execute their selected API request directly;
- all preset controls disable while a run is active, preventing overlapping result races;
- a staged INPUT → EXTRACT → GROUND → VERIFY processing state remains readable before the real
  result is shown;
- copy explicitly states that trace pacing is interface presentation, not model/network latency;
- active engine truth remains `regex-baseline-v1 · offline · deterministic gate`;
- stacked layouts bring the output region into view at run start and respect reduced-motion mode;
- custom form submission continues to use the same API and final BLOCK/PASS/REVIEW response.
