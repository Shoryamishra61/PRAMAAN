# T026 acceptance evidence

Requirements: `PRD-NFR-005`, `SRS-021`, `SRS-024`, `AI-009`, `AI-014`, `API-009`.

Verified on 2026-08-23.

Structured logs accept an allowlist of operational IDs, hashes, versions, measured latency, status, and failure class. Their closed schema has no raw-evidence, prompt, credential, or raw-response field. Webhook authentication, semantic extraction, grounding, and worker lifecycle emit safe JSON events. Adversarial evidence containing a prompt-injection string, an email, and a fake key was absent from captured logs; provider failure deterministically produced `REVIEW` with `F_MODEL_UNAVAILABLE`.

`GET /api/v1/health` now initializes/checks the local schema and reports actual durable queue state (`idle`, `work_pending`, `processing`, or `failed`), database reachability, inference mode, and the last completed-job timestamp when present. It exposes no credential or secret-presence state. SQL-injection text used as a queue filter remains a bound parameter and cannot alter the schema.

The first full gate exposed a real regression: app construction initialized SQLite before an invalid webhook was authenticated. Initialization was moved out of app construction and behind the health probe. The existing mutated-body/original-signature replay test now guards that invalid HMAC is rejected before any database file is created.
